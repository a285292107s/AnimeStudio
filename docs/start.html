你能拿它做什么

一句话：它把 Unity 游戏打好的资源包拆开，把里面的贴图、模型、动作、音频、着色器、文本，导成你电脑上能直接打开的文件。

包＝快递箱。一个游戏目录里有几百个箱子，箱子里还套着小盒子，游戏厂商管小盒子叫 CAB，真正的东西在小盒子里。AnimeStudio 干的活是：找到箱子、开锁、拆盒、把东西摆出来，最后按类型放进你指定的文件夹。

4种导出格式
3种导出范围
6列资产信息
75个游戏条目
它导出的东西和落地形态
你想拿的导出后是什么
贴图、立绘.png（默认），可选 .jpg .bmp .tga；光照贴图会存 .hdr
模型、动作.fbx；只要几何体时也可以单独导 .obj
音频.wav，或它原本的压缩容器 .fsb
着色器、文本、字体.shader、.txt、.ttf 或 .otf
看不懂的对象.json（字段全摊开）、.txt（字段文本）、.dat（原始字节）

它不改游戏本体，只有一个例外

它读别人的文件、把结果写进你选的输出目录。唯一例外是分片包：碎片会被拼成一个完整文件、写回碎片所在的目录。见疑难解答。

下载与运行

同一份下载里有三个程序：AnimeStudio.GUI.exe 是老的窗口界面；bin\AnimeStudio.Host.exe 是新的网页界面（推荐，自动找游戏、能看文本和图库）；AnimeStudio.CLI.exe 给脚本用。

只编 net10.0-windows 一个目标
包适合谁
.NET 10 版唯一的包，需要 .NET 10 Desktop Runtime

  1. 装 .NET 10 桌面运行时

    从 .NET Desktop Runtime 装 10。是 Desktop Runtime，不是普通 Runtime；只编了 Windows x64。

  2. 解压到任意目录

    没有安装程序，解压即用；放哪个盘都行，路径有中文也没事。

  3. 双击 run-host.cmd（或 bin\AnimeStudio.Host.exe）

    网页界面会自己从 miHoYo Launcher 的注册表和各盘常见目录里找星穹铁道、绝区零的安装位置；找不到时再点「更换」手动选。两款游戏各有各的输出目录：设置里两条路径并排显示、各自「选择」，默认在同一个根下分成 <根>\SR 和 <根>\ZZZ，也可以分别指到不同磁盘；改哪一款只影响哪一款，切换游戏时界面、图库、版本快照一起切过去，互不覆盖。旧版本只存一个共享根，启动时会自动拆成这两个目录，已经导出的文件原地不动。路径确认后点「重建索引」（每局一次，几秒），之后每次游戏更新点「提取」即可。

  4. 需要老界面就双击 GUI

    标题栏出现 AnimeStudio v1.1.0 就对了。首次启动会在程序旁边补一份密钥表 CNKeys.json，别删。

别把 exe 单独拷走

根目录只有几个 exe 和 LICENSE，其余 dll 全在 bin 子目录；网页界面整体也在 bin 里。exe 按相对路径去 bin 找部件，单独拷走就只会闪一下。

第一步 选对游戏

这是新手第一大坑，也是唯一「选错就全盘皆错」的步骤。Options ▸ Select Game 弹出的窗口从上到下三段，加一个 Confirm。

第一段 Game type
三个大类：Hoyo game、Encrypted game (pick if unsure)、Other。它决定下面两个下拉里装什么。
第二段 Game
具体游戏。第一段选 Hoyo game 时，这里列 7 个发行商名字（Genshin Impact、Honkai: Star Rail、Zenless Zone Zero 等）；另两项列单个游戏条目。
第三段 Game version
Live、CBT 1、CBT 2、CBT 3 之类，默认停在第一个。只有第一段选 Hoyo game 时才亮。

一共 75 个条目，光 Hoyo 系就占 17 个版本。别指望翻一翻就找到——先定厂商，再定版本。

三个大类的标签和名单对不上

按代码的实际行为走：Encrypted game (pick if unsure) 列的是 54 个加密游戏，标签写「不确定就选这个」，名副其实；Other 只列 3 个通用条目。找不到你的游戏，先翻第二项。

为什么必须选对：不同游戏用不同的锁和钥匙。选错时它拿 A 的钥匙开 B 的箱子，轻则列表空白，重则解出一堆名字乱码、尺寸不对、打不开的文件。它不会自动猜。

点完 Confirm，界面几乎没变化

正常的：选择只写进设置，下次加载才生效。想确认就开 Debug ▸ Enable console，日志里会有一行 Target Game is …。

第二步 加载

  1. 先试一个文件

    用 File ▸ Load file，随便挑一个 .bundle 或 CAB- 开头的文件。能解出一张立绘，就说明游戏选对了。

  2. 再整个目录

    确认没问题后，用 File ▸ Load folder 指向游戏资源目录。它会递归读所有子目录，第一次跑完整目录会很慢。

  3. 等状态栏走完

    加载期间左栏是空的，底部进度条在走，状态栏在刷。走完之前别急着点别的菜单项。

慢是有原因的：它先把整个目录扫一遍，把资产读进一张表；开跑前还按数据量的 8.5 倍估内存，超过剩余内存就弹窗问你要不要继续。

中途想停，用 File ▸ Abort

它只取消当前这一步，已读进来的不会自动清空，取消后资产数可能显示 0。看到 0 别急着说「里面没东西」，重新加载一次再看。

第三步 浏览与预览

左栏切到 Asset List：6 列，列名和顺序固定。

先用得上的只有三列：Name 是内部代号，Container 是它属于哪个小盒子，Type 是你过滤的依据。六列的逐条解释在界面导览里。

过滤有三条路：Filter Type 菜单按类型筛（菜单项按当前文件里出现过的类型动态生成）；Asset List 上方的搜索框；Scene Hierarchy 页的搜索框。后两个是正则，匹配 Name、Container、PathID 三列。

预览在右栏：图片、文本、音频、字体、网格都能点开；模型类要先在 Options ▸ Advanced 勾上 Model preview enabled。

预览不读贴图

它只把位置、法线、顶点色送进显卡，没有 UV，也不读材质。所以模型预览看到的是一团带明暗的灰白，这不是你操作错了——想看表面得导出。

第四步 导出

Export 菜单里是 3 种范围 × 4 种格式，共 12 个入口：范围三项在菜单最上面，格式分在 Raw、Dump、JSON 三个子菜单里，不带子菜单的那三项就是默认的 Convert。

4 种格式：先选「要什么」，不是「选哪种算法」
格式产物什么时候用
Convert（默认）按类型转：贴图变图片、模型变 FBX、音频变 WAV、文本变 TXT九成情况用它，目标是「人能直接打开」
Raw一律 .dat，原始字节不加工要自己写程序处理，或怀疑 Convert 转坏了
Dump一律 .txt，对象的字段文本想扒开看这个对象内部到底存了什么
JSON整个对象序列化成 .json想做版本对比、喂给别的工具
3 种范围：说的是「导哪些」，不是「导成什么」
范围具体导哪些
All assets当前加载进来的全部资产
Selected assets你在资产列表里选中的那几行
Filtered assets过滤后列表上看到的全部，类型筛选和搜索框都算

两个典型操作：只导立绘，先在 Filter Type 勾 Texture2D 和 Sprite，再 Export ▸ Filtered assets；只导一张，列表里选中它，再 Selected assets。点下去先选文件夹，然后才开导。

结束语里的 skipped 不一定是失败

跳过的原因有两个：解不出来，或者同名文件已经存在——默认不覆盖，遇到同名直接跳过。想连号重导，先清空输出目录，或者打开 Options ▸ Allow duplicates。

输出目录怎么排

排法由 Export Options 里的下拉决定，默认第一种，只影响目录结构，不影响导出内容。

四种布局
布局路径长什么样适合谁
ByType（默认）输出目录\Texture2D\、输出目录\AudioClip\想按类型翻，最简单
ByContainer输出目录\它原来的容器路径\想还原游戏里的目录结构
BySource输出目录\源文件名_export\内部文件名\想追溯每个文件来自哪个包
None全部平铺在输出目录根下只导几件东西时最省事

重名：默认不覆盖、直接跳过；打开允许重名后自动加序号（第二份叫 名字 (1).png），序号从 1 开始。资产名达到 260 个字符时，文件名会被换成随机名，之后认不出是谁。

你会遇到的文件长什么样

它判断文件类型靠读开头那几个字节，不看扩展名。所以改扩展名没用，也别因为「没有扩展名」就以为文件坏了。

资源目录里常见的东西
你看到的东西人话
.bundle、CAB- 开头、或没有扩展名快递箱：Unity 的资源包，开头写着 UnityFS
.assets、.resource、globalgamemanagers箱子里的清单：记着这个箱子里有什么
同目录的 .resS、.resource大件货物的实体：贴图和音频的真身
.block上百个加锁小包的合集，会逐个拆开读
开头是 ENCR加了锁的包，锁和钥匙按游戏不同
.split0、.split1…被切开的包，先拼回完整文件再读
blk、mhy0/mhy1、Blb 系、hyg 系、VFS 系各厂商自己的封箱方式，看文件头区分
以上都不像当资源流文件处理，通常是贴图音频的实体数据

单独拎一个 .assets 出来，常常导不出图

贴图实体常常不在 .assets 里，而在同目录的 .resS 里，清单里只有一个取货位置。找不到那个文件，这一项就会报错跳过，连图都不生成。第一次跑，请用 Load folder 让它把整个目录一起读进去。
