打不开

加载完一片空白，导出时状态栏说没有可导出资产

九成是游戏选错了，剩下一成是只加载了一个没有依赖的文件。它不看扩展名、只看文件头，而解密方式由你选的那个游戏条目决定；条目不对，箱子能认出来，盒子的锁打不开，资产表就是空的。

你可以：Options ▸ Select Game 重选，再用 File ▸ Load folder 整目录重来。

双击没反应，或者提示缺 .NET 桌面运行时

缺的是 .NET Desktop Runtime，不是普通的 .NET Runtime；而且它只支持 64 位 Windows。两个 exe 都是自宿主程序，你下的是哪个版本就要装哪个版本的桌面运行时，x64 架构。

你可以：按版本装对应的桌面运行时再双击；32 位系统没有可用的构建，换机器是唯一办法。

加载大目录跑到一半，内存爆掉

它在加载时把整个目录的资产塞进一张表，内存按数据量的 8.5 倍估算。单个包解压后小于 512MB 会整块放内存，超过就落成一个临时文件、关闭即删，但资产表本身还是全量。

你可以：分批加载、先按类型过滤再导出；或者开 Options ▸ Skip container recovery 少走一步（代价是 Container 列没有名字）；真跑不动就换 CLI，它一次只持有一个文件。

打开了但不对

资产名是乱码，导出的文件也打不开

游戏条目选错，它拿错了钥匙。每个条目自带一套解密参数，字节一旦错位，名字、尺寸、内容就全是垃圾——这不是编码问题，改系统区域设置也没用。

你可以：确认厂商和版本都对上（Live 与 CBT 是两套完全不同的锁），重选之后重新加载。

资产数量比游戏体积少得多

通常是你只加载了一个包，而不是全部。一个 .assets 只是清单，贴图实体常在同目录的 .resS 里；手动挑文件时，它只能顺着已经读进来的文件去找依赖。

你可以：用 File ▸ Load folder 整目录加载；目录太大就先做一份资产地图，精确定位之后再回捞。

模型是灰白的，看不到贴图

这是设计如此，不是导出坏了。3D 预览只把位置、法线、顶点色三样送进显卡，不读 UV、也不读材质；导出的 FBX 里同样只有几何体，材质会另外存在输出目录的 Materials 下，一个材质一份 json。

你可以：单独导出 Texture2D 拿到图，再在 3D 软件里手动挂上。

中文路径和超长文件名会不会出问题

中文路径没问题，超长文件名有问题。它全程走 Windows 的 Unicode 接口，中文目录名照常读写；但资产名达到 260 个字符时，导出文件名会被换成随机名，之后就认不出是谁了。

你可以：把输出目录放浅一点，导出前留意那些名字特别长的条目。

导出后不对

导出的贴图全黑，或者只有半张

多半是数据没找齐，不是图坏了。贴图实体常在同目录的 .resS 里，清单里只写了个取货位置；找不到那个文件，这一项会直接报错跳过，连图都不生成。压缩格式不认识时同样跳过。

你可以：整目录加载之后再导；还不行就换成 Raw 导出，拿到原始字节自己处理。

模型导出了，但 FBX 没有扩展名

这是 CLI 的已知问题，GUI 不受影响。走命令行导出 Animator 时，它把目录路径直接当成了 FBX 的文件名，产物没有 .fbx 后缀。

你可以：手动补上 .fbx 就能打开；或者改用 GUI 导出这一类资产。

音频导出来没有声音

先看扩展名。是 .wav 说明转成功了，没声音多半是播放器或音量问题；是 .fsb 说明它跳过了转换、把原始数据原样写了出来。只有 PCM、Vorbis、ADPCM、MP3、XMA 这几种能转 WAV，其它编码一律落成 .fsb（AAC 是 .m4a），普通播放器不认这两种容器。

你可以：用能读 FSB 容器的工具再转一次。

导出的数量比选的少

多数是「文件已经存在」，不是失败。默认不覆盖同名文件，遇到同名直接跳过；结束时那句跳过提示把「解不出来」和「已经有了」合并在一起，看不出区别。

你可以：清空输出目录重导，或者打开 Options ▸ Allow duplicates，让重名文件自动加序号。

程序本身

它会修改我的游戏文件吗

会写，但只写一种：分片包。加载前它会把 .split0、.split1 按顺序拼成一个完整文件，放回这些碎片所在的目录，然后才去读这个新文件；同名文件已存在就跳过，也不会删你的碎片。

你可以：先把游戏目录复制一份再动手，至少备份一次。

需要联网吗，杀毒软件报毒正常吗

不需要联网。唯一会联网的菜单项是从 GitHub 拉 Asset Index，它在源码里根本没接上事件，点了没有反应；其余功能全在本机跑。至于报毒：它要读别人的二进制、解密、再写出文件，exe 又没做数字签名，构建时还被改写过入口路径——这几样加在一起，杀软按行为打分很容易拦。仓库里没有关于误报的正式说明，所以这条只能你自己判断。

你可以：只从项目发布页下载，别用来路不明的包；确认来源可靠之后再决定要不要加白名单。

CLI 明明失败了，却返回 0

它的退出码永远是 0，别拿退出码判断成败。命令行入口拿到执行结果后没有把返回值传出去，内部异常也被吞掉，所以不管是导出失败还是路径写错，进程都正常退出。

你可以：用输出目录里的文件数量和日志内容判断，或者在外面包一层检查产物。
